# 回归评测

改提示词、换模型、调采样之前后跑一遍，用同一把尺比分数。**不做回归就会靠感觉。**

## 三个固定案例
| id | 案例 | 成片时长 | 基线 |
|---|---|---|---|
| `fireworks` | 放焰火 · 跨年晚会预热 | 2 分 03 秒 | 91（本台首次测量） |
| `station` | 人生站台 · 时间容器 | 6 分 35 秒 | — |
| `winter` | 冬日羽绒 · 15 秒产品短片 | 15 秒 | — |

案例写在 `eval/cases.cjs`。**改动案例就没法和历史分数比**，要加新案例请只往后加。

⚠️ **两把尺不要混**：本台的 AI 评委分（如 fireworks 91）与人工资讯稿评测的 70 分**不是同一把尺**。
台的价值在**同一把尺的前后差值**：改提示词/换模型后重新跑，看客观项和评委分往哪边动。

## 怎么跑
```bash
node eval/run.cjs                 # 跑三个案例（真实模型，约 10 分钟）
node eval/run.cjs fireworks       # 只跑一个
node eval/run.cjs --no-images     # 跳过出图/看图（省钱模式）
# 常规跑法已包含：出两张关键图 → 看图判断 → 逐页讲稿 → 执行八页 → 附录三件
node eval/score.cjs               # 客观检查 + AI 评委
npm run eval                      # 两步一起
```
产出：`eval/out/<case>.json`（原始产出）、`eval/results/<时间>.json`（结构化分数）、`eval/report-<时间>.md`（可读报告）。

## 把评测产出导进工作台看（不用看 JSON）
跑完 `node eval/run.cjs` 之后，回到界面：**创作工作台 → 更多 → 「导入评测案例到工作台」**。
每条案例会变成一条选题（打上评测来源标记），点开就能逐段看到当时的真实生成结果：① 创意与主题句候选、② 四幕与分场、③ 视觉规则与四张提示词、④ 逐页讲稿与附录三件。
导入是**幂等**的（同一条不会重复加），也**不会覆盖**你现有的任何内容。

## 两把尺
**客观检查（硬门槛，自动判，共 25 项）**：
- 脚本层：七段/四幕/主题句长度/视觉规则/时间轴段数/关键场次
- 视觉层：**四张提示词各不同**、**真的出图**、**看图判断已完成**、**看图时 imagesRead 必须为 true**、看图结论要有下一步
- 汇报层：讲稿页数与字数/执行八页/待核实与风险/**附录三件**（讲述顺序 ≥4 段、时长 8–20 分钟、拍摄清单 ≥5 条、答疑 ≥4 问）
- 防幻觉：**时间轴总长对得上成片时长（±15%）**、**没有空话词**、**没编造金额**、页面无报错

**AI 评委（同一把尺，跨版本可比）**：六个维度固定权重（A 10 / B 15 / C 10 / D 15 / E 20 / F 30），
按"能不能拿去汇报并进入拍摄"打分，并给出最该补的一件事。

## 怎么读结果
- **客观项掉了** → 一定是回归，先修这个，别急着看分数。
- **评委分掉了 3 分以上** → 看它给的 `why`，通常是某个维度的话术变味了。
- **tokens/用时涨了 50% 以上** → 检查是不是有调用误开了思考（视觉任务开思考会又慢又差）。
- **`retried > 0`** → 说明有 JSON 截断被兜底了，去看那一步是不是输出太长。
