## 1. 重建/排障时先做四件事

```bash
# 1) 谁占着 80/443？
ss -lntp | grep -E ':(80|443)\s'

# 2) Docker 里有没有本项目？
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'

# 3) 旧 Caddy 是不是 systemd 装的？
systemctl status caddy --no-pager 2>/dev/null | head -5

# 4) 域名到底解析到哪？
dig +short <域名> @8.8.8.8

# 5) 本机绕过 DNS 试探
curl -sI -H 'Host: <域名>' http://127.0.0.1/
```

对应处理：
- **A. 80/443 被 systemd 的 caddy 占着**（老尝试残留）→ `systemctl stop caddy && systemctl disable caddy`，再交给 compose 里的 Caddy。
- **B. docker 里有 `vps-caddy-1` / `vps-lance-1`** → `cd /opt/jinhua/deployment/vps && docker compose logs --tail=80 caddy` 看 ACME 报错。
- **C. `dig` 没返回 119.28.20.166** → 先改 DNS，再重启 Caddy（证书会自动重试）。

## 5. 配置 `.env`（含模型密钥，权限 600）

```bash
cd /opt/jinhua/deployment/vps

# 5.1 从本机传密钥（本机执行）
scp -i ~/.ssh/tencent_hk_ed25519 \
  "/Users/lancelai/Documents/ChatGPT/个人/JINHUA/.env" \
  root@119.28.20.166:/opt/jinhua/deployment/vps/.env

# 5.2 服务器上追加站点变量（域名替换成你的真实域名）
cat >> .env <<'EOF'
SITE_ADDR=<域名>
PUBLIC_URL=https://<域名>
ALLOWED_HOSTS=<域名>
EOF
chmod 600 .env
```

要点：
- `SITE_ADDR` 只写域名，**不要带 `https://`**；`PUBLIC_URL` 才带 `https://`，且不要结尾斜杠。
- `ALLOWED_HOSTS` 与域名一致（`studio_server.py` 里 Host 校验会用它，否则全站 403）。

## 13. CDN / 大陆加速：先实测再决定

| 方案 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| Cloudflare 免费 | DNSPod 改 NS 到 Cloudflare，记录开橙云 | 隐藏源站、免费 WAF、静态缓存 | 大陆访问 Cloudflare 免费线路不稳定，**动态 API 可能更慢** |
| 腾讯云 EdgeOne | 域名接入 EdgeOne，回源 119.28.20.166 | 同厂商线路、只加速静态、安全防护 | 要控制台接入 + 按量计费；动态请求仍回香港 |
| 不做 CDN | 保持直连香港 | 最简单、故障面最小 | 无加速 |

建议：**先上线「手机上传 + 访问保护」，再用手机 4G 实测首屏与上传耗时**（目前香港直连约 180ms 建连、报价页 1–2s）；如果实测体感可接受，就不加 CDN——对动态上传类请求，CDN 收益很小，反而多一层故障点。
