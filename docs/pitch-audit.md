# 汇报逻辑体检 · studio-audit.js

> 规则先查结构（免费、可复现），模型只judge规则查不出的判断问题；**引用必须能在原文里原样找到**，摘抄不出来的一律丢弃。

## 为什么需要它

模板本身没问题（10 页单条 / 14 页专场每一页都写了它要回答的问题），问题是**填进去的内容没人检查**。这份工程把"逻辑混乱"拆成 11 条可判定的规则，先由代码拦下结构性问题，再让模型处理只有人能判断的部分。

## 输入

直接吃你现有的汇报数据结构，不需要新格式：

```js
{
  title, audience:'老板', purpose:'单条'|'专场',
  origin,                       // studio-origin 的创意单元（有则做闭环检查）
  chapters:[{id,title,section,group,enabled,task}],   // 你现有的提纲定义
  pages:[{slotId,title,section,basis,points:[],notes,evidence,frameIndices:[]}],  // 你现有的正文页
  facts:{confirmed:[],assumed:[]}                     // 专场模板要求的“需求／事实／假设分开”
}
```

## 11 条规则（前 9 条免费跑，不需要模型）

| 规则 | 判什么 | 级别 |
|---|---|---|
| R01 | 提纲要求的页面缺了 | 必须改 |
| R02 | 有页面没有正文要点／没有讲稿 | 必须改／建议改 |
| R03 | 没标依据性质；声称"事实"却没出处 | 必须改 |
| R04 | 摘要页的主张与已确认主张是两套说法 | 建议改 |
| R05 | 拍摄落地的天数与出发点确认的代价不一致 | 必须改 |
| R06 | 没把需求／事实／假设分开；**把假设写成了事实** | 建议改／必须改 |
| R07 | 空话词（赋能／打造／沉浸式／引爆／破圈／闭环…） | 超 5 个必须改 |
| R08 | 结尾不是决策清单；决策项 > 8 条；说不出要老板决定什么 | 必须改／建议改 |
| R09 | 没有回答"哪里可能失败" | 必须改 |
| R10 | 没有可指导拍摄的画面清单；画面缺场地／机位／光／人 | 建议改／必须改 |
| R11 | 场地尺寸前后不一致 | 建议改 |

## 模型只做四件判断

1. 每页有没有回答它在提纲里承担的问题（`task`）
2. 关键画面是**支撑主张**，还是只是好看
3. 有没有两页互相矛盾
4. 老板最可能问的三个问题，现在答得上吗

**防幻觉闸门**：每条必须给出 `quote`（该页原文里原样摘抄 ≥6 字）。系统用规范化后的字符串匹配，匹配不上就丢弃并计数（`audit.ai.dropped`）——模型编不出"页面上没有的话"。

## 输出与结论

```js
audit = { rules:[], ai:{findings,dropped}, findings:[], verdict:{level,label,blockers,warns} }
verdict.level ∈ 可汇报 / 可汇报（有建议）/ 需修改
```

## 真实跑一遍

故意做一份有问题的汇报（摘要页换了主张、落地页写成 3 天、假设写成事实、缺风险页），实际输出：

```
结论： 必须改 3 项
---
[必须改]拍摄落地写的天数（3天）与出发点确认的代价（1天）不一致｜原文：3天 → 回去改一个：要么改代价，要么改方案，别让老板看到两个数
[必须改]（production）把假设写成了事实：老式居民楼｜原文：老式居民楼 → 加“假设”或“预计”，并写清假设不成立的代价
[必须改]没有回答“哪里可能失败” → 专场模板明确要求这一页；补风险与替代方案
[建议改]（summary）这一页的主张与已确认的主张不一致｜原文：用一扇朝东的窗，拍妈妈把没寄出的信读给女儿听 → 把主张原样带过来，或回出发点改主张，不要两套说法
```

## 最小接入

```js
const deck={...现有汇报数据, origin:unit, facts:{confirmed:[],assumed:[]}};
const rules=StudioAudit.scan(deck);                        // 免费，先拦结构性错误
const {text}=await api('chat',{purpose:'refine',prompt:StudioAudit.prompt(deck,rules),references:[]});
const audit=StudioAudit.run(deck,JSON.parse(text));        // 合并 + 丢弃编造引用 + 出结论
if(audit.verdict.level==='需修改') 阻止导出“完整版”，只允许“讨论稿”
```

> 建议：`需修改` 时按你现有习惯把导出自动降级为"方向讨论稿"，和缺项不能导出完整版是同一个机制。
